1. 安装与快速验证（Claude Code 插件）

验证：

  • 新建/恢复一个项目会话，历史上下文应自动被注入（带”Token 经济学/节省比例”等头部信息）
  • 访问 Web Viewer：http://localhost:37777 能看到实时记忆流与统计

常见错误与排查：

  • 端口占用：37777 已被占用 → 释放端口或在设置中调整 CLAUDE_MEM_WORKER_PORT，并重启 worker
  • 原生模块 ERR_DLOPEN_FAILED：首次安装或原生模块不匹配时会触发，插件会清理安装标记并提示”重启 Claude Code 自动修复”
  • 版本不匹配：插件版本与 worker 版本不同 → worker 会执行自检并自动重启对齐

3. 配置（~/.claude-mem/settings.json）

关键项与默认值（由 SettingsDefaultsManager 注入）：

Provider 与模型：

  • CLAUDE_MEM_PROVIDER: claude | gemini | openrouter（默认 claude）
  • CLAUDE_MEM_MODEL: claude-sonnet-4-5
  • CLAUDE_MEM_GEMINI_API_KEY: “”
  • CLAUDE_MEM_GEMINI_MODEL: gemini-2.5-flash-lite
  • CLAUDE_MEM_GEMINI_RATE_LIMITING_ENABLED: true（免费层节流）
  • CLAUDE_MEM_OPENROUTER_API_KEY: “”
  • CLAUDE_MEM_OPENROUTER_MODEL: xiaomi/mimo-v2-flash:free
  • CLAUDE_MEM_OPENROUTER_MAX_CONTEXT_MESSAGES: 20
  • CLAUDE_MEM_OPENROUTER_MAX_TOKENS: 100000

系统与模式：

  • CLAUDE_MEM_WORKER_HOST: 127.0.0.1
  • CLAUDE_MEM_WORKER_PORT: 37777
  • CLAUDE_MEM_DATA_DIR: ~/.claude-mem
  • CLAUDE_MEM_LOG_LEVEL: INFO
  • CLAUDE_MEM_MODE: code（非 code 模式会从模式配置中接管”观察类型/概念”过滤）

上下文注入参数（Context Engineering）：

  • CLAUDE_MEM_CONTEXT_OBSERVATIONS: 50（时间线总观察条数）
  • CLAUDE_MEM_CONTEXT_FULL_COUNT: 5（展开详情的观察数量）
  • CLAUDE_MEM_CONTEXT_FULL_FIELD: narrative | facts（默认 narrative）
  • CLAUDE_MEM_CONTEXT_SESSION_COUNT: 10（包含的最近会话数）

  • CLAUDE_MEM_CONTEXT_OBSERVATION_CONCEPTS: 默认概念集合（如 files, tests, plans, etc.）

4. 搜索：三层工作流（MCP 工具 & HTTP API）

工作流（10x Token 节省理念）：

  1. search → 先取精简索引（ID、摘要）
  2. timeline → 对感兴趣的命中点拉取上下文时间线
  3. get_observations → 只对筛选后的 ID 拉取全文详情

HTTP 路由速览（部分）：

检索：

  • 统一检索：GET /api/search?query=...&type=observations&limit=20
  • 时间线：GET /api/timeline?anchor=123 或 GET /api/timeline?query=...
  • 观察按类型/概念/文件：
    • GET /api/search/by-type?type=bugfix&limit=10
    • GET /api/search/by-concept?concept=discovery&limit=5
    • GET /api/search/by-file?filePath=src/services/context/ContextBuilder.ts

上下文：

  • GET /api/context/recent?project=xxx&limit=3
  • GET /api/context/preview?project=xxx
  • GET /api/context/inject?projects=a,b&colors=true

Claude Desktop 技能与 mem-search： 对话内自然语言查询你的项目历史，底层走上述”三段式”检索。

5. 最佳实践（Context Engineering / Progressive Disclosure）

  • 渐进披露：先小索引后放大，严格按需取全文，避免把”项目史书”全塞进上下文
  • Token 经济学面板解读：
    • Header 会展示读取/工作 Token、节省金额与百分比（由 ContextBuilder + TokenCalculator 汇总）
    • CLAUDE_MEM_CONTEXT_FULL_COUNT 控制”展开全文”的条目数，谨慎调大
  • 过滤策略：在 code 模式外，可通过 ModeManager 的模式配置一次性切换”观察类型/概念”集合
  • 私密数据：用 <private> 标签，避免泄漏与污染长期记忆

二、机制篇

1. 生命周期钩子（Hooks）

核心事件（源码/文档约定）：

  • SessionStart
  • UserPromptSubmit
  • PostToolUse
  • Stop
  • SessionEnd

Smart Install： 非生命周期钩子，负责依赖缓存/检测，加速并稳定首次安装与升级体验。

作用： 在各事件点采集”观测（observations）/摘要（session_summaries）/用户提示（prompts）”并入库，为后续上下文注入与检索提供素材。

2. Worker 架构（协调层）

src/services/worker-service.ts：300+ 行的”薄协调器”。

职责：

  • 服务器与路由：src/services/server/*（Express），注册 Viewer/Session/Data/Search/Settings/Logs 等路由；对 /api/context/inject 提供”初始化等待”防 404
  • MCP 客户端：通过 Stdio 连接内部 mcp-server.cjs，为搜索工具链提供代理
  • 进程与健康：
    • Orphan Reaper 定期清理孤儿子进程（Issue #737）
    • Pending Queue 恢复：冷启动自动恢复未完成队列（如崩溃后）
    • 版本自检 + 自动重启；PID 文件与健康检查；优雅停机（信号处理与 httpShutdown）
  • SSE 广播：向 Web Viewer 推送处理状态（队列深度、活动会话）

管理 API（节选）：

  • /api/pending-queue（查看/处理/清理）
  • /api/stats、/api/projects、/api/processing-status

3. 数据面：SQLite + 迁移 + FTS5

主要表（见 src/services/sqlite/migrations.ts v1-v7）：

  • sessions：会话元信息
  • memories：压缩片段（v2 引入层次字段）
  • overviews：历史版本摘要表（后由 session_summaries 取代）
  • sdk_sessions：SDK 会话（content/memory 双 ID）
  • observations：关键观测（含 type、title、subtitle、narrative、facts、concepts、files_read、files_modified、discovery_tokens 等）
  • session_summaries：结构化会话摘要（request/investigated/learned/completed/next_steps/notes/…）
  • FTS5 虚表：observations_fts、session_summaries_fts（含触发器维护增删改同步）

ROI 度量： discovery_tokens 记录发现/生成各观测与摘要的 Token 成本，为经济学面板提供依据。

入库路径： 如 storeObservation(db, contentSessionId, project, obs, ...) 将结构化 JSON 写入 observations。

4. 上下文构建链路（Context）

调用链： ContextConfigLoader → ObservationCompiler → ContextBuilder

  • ContextConfigLoader：读取 ~/.claude-mem/settings.json；在非 code 模式下由 ModeManager 的模式配置接管”观察类型/概念集合”
  • ObservationCompiler：按类型/概念/项目查询最近观察与摘要，组装时间线，并解析”上次会话的 assistant 消息”
    • Transcript 路径：~/.claude/projects/<cwd-用-替换斜杠>/<sessionId>.jsonl
    • 多项目：queryObservationsMulti/querySummariesMulti 支持 worktree 合流
  • ContextBuilder：
    • 计算 Token 经济学
    • 渲染 Header/Timeline（含 fullObservationIds 展开）/最近摘要/Previously/Footers
    • useColors=true 时输出 ANSI 彩色（终端友好）

空态处理： 无数据时输出友好的空态提示（Markdown/ANSI 两种）。

5. 搜索面（SearchManager + 路由）

  • 统一检索：GET /api/search（observations/sessions/prompts）与 GET /api/timeline
  • 语义捷径：/api/decisions、/api/changes、/api/how-it-works
  • 细分维度：/api/search/by-type、/api/search/by-concept、/api/search/by-file
  • 上下文相关：/api/context/recent、/api/context/timeline、/api/context/preview、/api/context/inject
  • 分页与直取：/api/observations、/api/summaries、/api/observation/:id、批量 /api/observations/batch

6. Session ID 设计（关键）

双 ID：

  • contentSessionId（用户在 Claude Code 的对话 ID）
  • memorySessionId（SDK agent 内部会话 ID，用于 resume）

流程：

  1. Hook 先创建 sdk_sessions，memory_session_id 为空
  2. 首条 SDK 消息返回真实 session_id → 回写到 memory_session_id
  3. 后续请求才使用 resume: memory_session_id（严禁用 contentSessionId）

观测入库为何用 contentSessionId： 观测在整个用户会话生命周期保持稳定关联，避免 resume 语义混淆；详见 docs/SESSION_ID_ARCHITECTURE.md。

7. 集成

  • Cursor：CursorHooksInstaller 自动安装/更新 hooks，与 Cursor IDE 集成上下文与命令
  • Claude Desktop 技能：对话中直接查询持久化记忆，底层复用三段式检索与 HTTP API

三、故障排查

  • 端口被占用（37777）：
    • bun plugin/scripts/worker-service.cjs status 查看；占用则 stop 再 start；或改 CLAUDE_MEM_WORKER_PORT
  • 原生模块 ERR_DLOPEN_FAILED：
    • Context 初始化捕获该错误后会清理 ~/.claude/plugins/marketplaces/thedotmack/plugin/.install-version 标记，并提示重启 Claude Code 自动 rebuild
  • 版本不匹配自动重启：
    • Worker 健康检查到插件版本与自身不一致时，先 httpShutdown 再等待端口释放并重启
  • 数据库健康：
    • ~/.claude-mem/claude-mem.db 存在与大小；/api/stats 统计；FTS5 表和触发器创建是否成功
  • 权限与路径：
    • ~/.claude-mem、~/.claude/projects 可写；Windows 上注意路径与 PID 文件权限
  • 队列卡死/遗留：
    • /api/pending-queue 查看；/api/pending-queue/process 触发恢复；/api/pending-queue/failed 或 /all 清理
