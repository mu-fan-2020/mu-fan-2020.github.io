项目备忘录

这里用来记录「我看到了、觉得有意思，但不一定会立刻动手」的项目。
每个项目互相独立，只写清楚：这是啥、为啥记它、现在做到哪一步。

ezBookkeeping

类型：自托管记账系统（Web 应用）
链接：https://github.com/mayswind/ezbookkeeping
当前状态：已在内网部署，研究 API / MCP 接入中

这是个什么项目？
一个轻量级的个人记账 Web 应用，可以自己在服务器上部署。支持多账户、多币种、账单导入、搜索和统计图表，也提供 API / MCP 接口，方便被其他工具或 Agent 调用。

我为什么记它？以后可能怎么用？
目标是让 AI 助手直接连到这个系统，自动做月度/年度消费分析、分类汇总、异常支出提醒，尽量减少手动导出和整理。

AiToEarn

类型：内容营销 / 多平台分发系统
链接：https://github.com/yikart/AiToEarn
当前状态：代码已克隆本地，处于架构研究阶段

这是个什么项目？
一个开源的内容营销平台，支持一键多平台发文、热点追踪、评论数据收集和分析。后端用 Docker 可以一键起服务，自带数据库、队列等组件。

我为什么记它？以后可能怎么用？
主要关注它的整体架构设计和 MCP 接入方式。以后如果要做自己的「内容中枢」或个人品牌运营工具，可以借鉴它的数据流设计，而不一定直接使用它的前端。

ai-architecture

类型：AI 系统架构文档合集
链接：https://github.com/MyInvestPilot/ai-architecture
当前状态：文档已拉到本地，慢慢消化中

这是个什么项目？
一套关于 AI 原生系统设计的文档合集，涵盖 AI 驱动开发流程、混合 Agent 架构、个人基础设施搭建等内容，更偏「方法论」和「架构图」，不是一个可以直接部署的产品。

我为什么记它？以后可能怎么用？
对设计「个人 AI OS」这类系统很有参考价值。以后在做出题系统、账本分析系统、内容分发系统时，可以从这里借一些架构思路和实践案例。

OpenSpec

类型：Spec 驱动开发框架
链接：https://github.com/Fission-AI/OpenSpec
当前状态：持续演进中，不定期会有新想法和实践

这是个什么项目？
一个用规范（Spec）来驱动 AI 写代码的框架。核心思想是先用结构化的规范描述需求和接口，再由 AI 根据这些规范生成实现，避免「聊天式开发」的混乱。

我为什么记它？以后可能怎么用？
这是自己在做的长期项目，用来提升 AI 辅助开发的可控性。未来和任何新系统（比如出题系统、各种 Agent 服务）结合时，都希望先有 Spec 再写实现。

awesome-openclaw-usecases

类型：OpenClaw 使用案例 / 资源合集
链接：https://github.com/hesamsheikh/awesome-openclaw-usecases
当前状态：已收藏，准备后面挑典型场景深入看

这是个什么项目？
一个围绕 OpenClaw 的「awesome 列表」，收集了各种使用场景、示例项目和实践资源，方便快速了解别人是怎么用 OpenClaw 搭东西的。

我为什么记它？以后可能怎么用？
以后在设计自己的用例、Skill、集成方案时，可以参考这里的案例，把有价值的模式搬到自己的个人 AI OS 里，避免闭门造车。

visual-explainer

类型：Agent 可视化说明 / HTML 报告生成 Skill
链接：https://github.com/nicobailon/visual-explainer
当前状态：已收藏，后续接 IDE / Coding Agent 时考虑集成

这是个什么项目？
一个 Agent Skill，用来把复杂的终端输出（架构说明、diff review、计划审查、数据表等）转成带样式的独立 HTML 页面，而不是单纯的 ASCII 图和表格。支持暗色/亮色主题、Mermaid 图表、交互式缩放。

我为什么记它？以后可能怎么用？
以后在做代码审查、架构回顾、计划审计时，可以用它把”Agent 的分析结果”变成可读性很强的 HTML 报告，方便在浏览器里看、发给别人、或嵌到知识库里，比纯终端输出更适合长期保存。

ClawRag

类型：OpenClaw 专用 RAG 后端 / 长期记忆引擎
链接：https://github.com/2dogsandanerd/ClawRag
当前状态：已收藏，未来作为「个人 AI OS 长期记忆 / 教材 RAG」的候选方案

这是个什么项目？
一个为 OpenClaw 定制的 RAG 系统，用 Docling 做文档解析、用 ChromaDB 做向量存储，通过统一的 HTTP API 对外提供”长文本检索 + 问答”能力，可以被 OpenClaw 当成长期记忆/知识库后端来用。

我为什么记它？以后可能怎么用？
未来如果要给个人 AI OS 搭一套统一的知识大脑（比如装教材 PDF、项目文档、博客归档），可以考虑直接用它做 RAG 中枢，让 OpenClaw 通过 API 调它做检索，而不是自己从零搭 Docling + 向量库。

llmfit

类型：本地 LLM 模型选型 / 评估工具
链接：https://github.com/AlexsJones/llmfit
当前状态：已收藏，后续在有 GPU 的机器上做本地模型选型时使用

这是个什么项目？
一个命令行工具，内置了近百个模型和数十个 Provider 的配置。它会自动检测机器的 CPU、内存、GPU、显存等硬件信息，然后根据”能不能跑、速度、质量、上下文长度”给模型打分，帮你筛出在当前机器上最合适的模型和量化方案。

我为什么记它？以后可能怎么用？
适合用在将来搭建本地 LLM 节点时做”第一轮体检”：先用它看这台机器适合跑哪些 7B/13B/70B 模型、用什么量化，再决定实际部署什么模型。也可以作为自动选型脚本/Agent 的一环，输出 JSON 结果给其它工具消费。

awesome-llm-apps

类型：LLM 应用案例 / 模板合集
链接：https://github.com/Shubhamsaboo/awesome-llm-apps
当前状态：已收藏，后续设计和实现自己 Agent / RAG 应用时作为案例参考

这是个什么项目？
一个整理好的 LLM 应用示例合集，按场景分类收集了大量基于 RAG、AI Agents、多 Agent 团队、MCP、语音助手等模式构建的开源项目，覆盖代码助手、数据分析、内容创作等不同领域。

我为什么记它？以后可能怎么用？
在设计个人 AI OS 里的新能力（比如出题系统、账本分析 Agent、内容管家）时，可以参考这些应用的任务拆分方式、交互流程和技术栈选型，用来对照和借鉴，而不是从零闭门造车。

PentAGI

类型：AI 驱动的自动化渗透测试系统 / 安全研究平台
链接：https://github.com/vxcontrol/pentagi
当前状态：仅作为参考项目记录，尚未在本机部署或运行

这是个什么项目？
PentAGI（Penetration testing Artificial General Intelligence）是一个多 Agent 驱动的自动化渗透测试平台。它把安全测试拆成多个专职 AI Agent（情报收集、漏洞研究、利用开发、基础设施等），结合长期记忆系统和 Neo4j 知识图谱，配合内置浏览器、Tavily/Perplexity/Google CSE 等外部搜索，用类似”AI 红队作战室”的方式执行渗透测试任务。整体通过 Docker 沙盒运行，并提供 Grafana/Prometheus 监控和详细报告输出。

我为什么记它？以后可能怎么用？
短期内不会直接在生产环境或当前 OpenClaw 主机上部署，主要把它当成”多 Agent + 安全场景”的架构教材来参考：

  • 看它如何设计安全测试 Agent 团队的分工与协作；
  • 学习它的长期记忆、知识图谱和情报收集链路，对以后做「个人资产安全自检 Skill」有借鉴价值；
  • 未来如果要在单独、安全隔离的环境里给自己服务做体检，可以考虑选其部分组件和工作流思路，而不是整套照搬。

Social-Media-Trend-Tracker

类型：全面的 Twitter/Reddit 社交媒体趋势分析系统
链接：https://github.com/AbhayAyare/Social-Media-Trend-Tracker
当前状态：已查阅评估

这是个什么项目？
一个基于 Python 的数据分析项目，通过 Twitter API 和 Reddit Pushshift API 收集数据，运用 NLP 和机器学习技术，分析社交媒体趋势、用户情绪和新兴话题，并支持 Streamlit 仪表盘可视化。

我为什么记它？以后可能怎么用？
它功能全面，能够同时追踪 Twitter 和 Reddit 的通用热点并进行情感分析。如果需要构建一个通用的社交媒体数据分析平台，其纯 Python 的实现和清晰的架构值得借鉴。核心逻辑可以由 Agent 调用来生成报告。

reddit-ai-trends

类型：Reddit AI 趋势智能报告生成器
链接：https://github.com/liyedanpdx/reddit-ai-trends
当前状态：已查阅评估

这是个什么项目？
一个专注于 Reddit 上 AI 领域趋势的自动化报告工具。它利用 Reddit 官方 API 获取帖子，结合 LLM 进行多模态内容分析（图片、YouTube 视频、网页内容总结），深入总结关键讨论并追踪趋势。每日生成中英文 Markdown 报告，并通过智能缓存优化 API 成本。

我为什么记它？以后可能怎么用？
如果重点是追踪 Reddit 上 AI 领域的热点，并需要高质量、智能化的内容总结和趋势分析，这个项目是绝佳选择。其直接生成 Markdown 报告和 LLM 深度分析的特性，使其非常适合由 Agent 集成和定期生成报告。

Canary-The-social-media-monitor

类型：多平台社交媒体监控与趋势预测系统
链接：https://github.com/Neel-G-png/Canary-The-social-media-monitor
当前状态：已查阅评估，不建议直接集成到 Agent

这是个什么项目？
一个集成了 Reddit、YouTube 和 Twitter 数据的社交媒体监控系统。其核心亮点在于能够通过分析历史数据，预测内容（如点赞、转发）的受欢迎程度。项目包含 React 前端、Flask 后端和 MySQL 数据库，提供数据可视化仪表盘。

我为什么记它？以后可能怎么用？
尽管功能强大且涵盖多平台，但其复杂的 Web 应用架构（React/Flask/MySQL）使其非常不适合直接作为 Agent 的技能模块。部署和集成难度极高，更适合作为独立运行的服务。主要作为参考，学习其多平台数据集成和趋势预测的思路。

BookLore

类型：自托管多用户数字图书馆 / 阅读管理系统
链接：https://github.com/booklore-app/booklore
当前状态：已收藏，后续考虑在内网部署做「个人图书馆中枢」

这是个什么项目？
BookLore 是一个自托管的多用户数字图书馆，支持通过 Docker 一键部署。它提供智能书架（规则驱动的 Magic Shelves）、自动元数据抓取（封面、简介、评分和评论）、内置 EPUB/PDF/漫画阅读器，以及基于 OPDS 的设备同步，兼容 Kobo、KOReader 等阅读设备。

我为什么记它？以后可能怎么用？
它非常适合做「个人/家庭图书馆中枢」：把散落在各处的电子书集中管理，统一做分类、搜索和进度同步。以后可以考虑：

  • 在内网起一个实例，把现有 EPUB/PDF 书库接进去；
  • 让 OpenClaw / Agent 通过 OPDS 或 API 读取书库信息，做「读书进度追踪、推荐下一本、基于书单的学习计划」等自动化；
  • 结合现有的记笔记/知识库系统，把阅读记录和项目备忘录打通。

huge-ai-search

类型：AI 搜索工作流规范 / 深度追问策略模板
链接：https://github.com/wangwingzero/huge-ai-search
当前状态：已收藏，准备在 Coding Agent / OpenClaw Skills 中内化其搜索策略

这是个什么项目？
这是一个围绕 MCP 工具 mcp_huge_ai_search_search 设计的「搜索优先」工作流规范，重点不是代码本身，而是一整套 AI 如何先搜索、再多轮追问、再行动的流程。它定义了什么时候必须搜索、追问哪些问题（场景化、避坑、最佳实践）、以及 Bug 修复和架构设计时的通用问法模板。

我为什么记它？以后可能怎么用？
对我这种重度依赖 Agent 的工作流来说，它更像一份「AI 搜索守则」：

  • 以后可以把里面的触发条件和追问模板，内化到 coding-agent / OpenSpec / OpenClaw Skills 里，让所有子 Agent 在高风险改动前强制先搜再干；
  • 也可以作为写自己搜索 Skill 文档的蓝本，约束 AI 在遇到架构设计、性能优化、bug 修复这类高风险任务时不瞎拍脑袋，而是遵守一套固定的深度追问流程。

openclaw-memory

类型：OpenClaw 原生记忆管理 Skill
链接：https://github.com/geq1fan/openclaw-memory
当前状态：待评估部署

这是个什么项目？
一个专为 OpenClaw 设计的自动记忆管理系统。通过两个定时任务（memory-writer 和 memory-janitor）自动扫描对话记录、提取关键信息、归档旧日志，并维护 MEMORY.md。内置知识验证功能，能自动检测过时、重复、孤立、冲突的信息。

我为什么记它？以后可能怎么用？
目前 JARVIS 的记忆完全靠手动维护，经常忘事。这个方案最轻量（只需 2 个 cron 任务），原生集成 OpenClaw，安装简单。如果效果好，可以解决记忆遗忘问题，让 AI 助手真正”记住”历史对话。

ClawIntelligentMemory

类型：OpenClaw 智能记忆系统解决方案
链接：https://github.com/denda188/ClawIntelligentMemory
当前状态：待评估部署

这是个什么项目？
一套三层架构的智能记忆管理系统（每日日志 → 精选记忆 → 长期归档）。通过 LLM 智能提取关键信息（从 150 行日志提取 3-5 个关键项），包含检查点系统、决策日志、模式提取、主动优化、动机系统等 6 大功能模块。作者声称效率提升约 16 倍。

我为什么记它？以后可能怎么用？
功能比 openclaw-memory 更完整，有决策追溯、模式分析、成就系统等高级功能。如果基础的记忆管理不够用，可以考虑升级到这个方案。适合需要深度分析和长期记忆优化的场景。

PowerMem

类型：企业级 AI 记忆基础设施
链接：https://github.com/oceanbase/powermem
当前状态：待评估部署

这是个什么项目？
OceanBase 出品的生产级记忆系统。在 LOCOMO 基准测试中，准确率提升 48.77%、响应速度提升 91.83%、Token 消耗减少 96.53%。支持智能记忆提取、艾宾浩斯遗忘曲线、用户画像、多智能体隔离、多模态（文本/图片/音频）、混合检索（向量+全文+图数据库）。提供 Python SDK、HTTP API、MCP Server 三种集成方式。

我为什么记它？以后可能怎么用？
如果 JARVIS 和 Friday 两个 bot 需要独立记忆空间但又能共享部分信息，PowerMem 的多智能体支持很合适。性能指标也很强，适合长期使用。但需要配置数据库（OceanBase/PostgreSQL/SQLite），部署成本比前两个高。

memU

类型：24/7 Agent 长期记忆框架
链接：https://github.com/NevaMind-AI/memU
当前状态：已部署但停用（最后更新 2026-02-12）

这是个什么项目？
一个为 24/7 运行的 AI Agent 设计的记忆框架，作为主 agent 的”记忆侧车”运行。支持监控对话、抽取记忆、预测意图，可以用 in-memory 模式或 Postgres + pgvector 持久化。需要 Rust + Python + Postgres 环境。

我为什么记它？以后可能怎么用？
2 月 12 日测试过，服务还在跑但没有真正接入工作流（数据库里有 78 条资源 + 311 条记忆，但都是测试数据）。功能相对基础，不如 PowerMem 完善。暂时不考虑重启，除非其他方案都不合适。

MiroFish

类型：群体智能引擎 / AI 预测系统
链接：https://github.com/666ghj/MiroFish
当前状态：已查阅评估

这是个什么项目？
一个基于多智能体技术的新一代 AI 预测引擎。通过提取现实世界的种子信息（新闻、政策、金融信号），自动构建高保真平行数字世界。成千上万个具备独立人格、长期记忆与行为逻辑的智能体在此自由交互与社会演化。用户可通过「上帝视角」动态注入变量，精准推演未来走向。

我为什么记它？以后可能怎么用？
核心思路是「让未来在数字沙盘中预演」。对设计复杂系统的预测和推演很有参考价值：

  • 学习其多 Agent 架构设计和群体智能模拟方法；
  • 借鉴「种子信息 → 数字孪生 → 推演预测」的工作流；
  • 未来在做政策/市场/舆情预测类项目时，可以参考其架构思路。

WorldMonitor

我为什么记它？以后可能怎么用？
对构建实时监控和情报分析系统很有参考价值：
