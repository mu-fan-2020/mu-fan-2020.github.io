项目简介

everything-claude-code 是一个完整的 Claude Code 配置集合，包含：

  • 15+ Agents - 专门的子代理（planner、architect、code-reviewer 等）
  • 30+ Skills - 工作流定义（TDD、持续学习、验证循环等）
  • 20+ Commands - 斜杠命令（/plan、/tdd、/verify 等）
  • Rules - 始终遵循的指南（安全、编码风格、测试等）
  • Hooks - 事件触发的自动化（内存持久化、格式化等）
  • MCP 配置 - 外部服务集成（GitHub、Supabase、Vercel 等）

项目地址: https://github.com/affaan-m/everything-claude-code

作者背景: 2025 年 9 月 Anthropic x Forum Ventures 黑客松获奖者，完全使用 Claude Code 构建了 zenith.chat。

核心工作流

标准开发流程

开发新功能的推荐流程：

流程说明

  1. 规划先行 - /plan 会重述需求、识别风险、创建分步计划，等待您确认后才动手
  2. 测试驱动 - /tdd 遵循 RED-GREEN-REFACTOR 循环
  3. 自动修复 - /build-fix 自动诊断和修复构建错误
  4. 质量保证 - /code-review 检查代码质量、安全性、可维护性
  5. 全面验证 - /verify 运行验证循环确保一切正常

常用命令详解

1. /plan - 规划命令

用途: 在开始编码前创建详细的实施计划

输出内容:

  • 重述需求（确保理解正确）
  • 分阶段实施计划
  • 识别依赖和风险
  • 估算复杂度和时间

使用场景:

  • 开始新功能
  • 重大架构变更
  • 复杂重构
  • 需求不明确时

示例:

关键特性: 会等待您确认后才开始写代码。如果计划不满意，可以回复 modify: [修改内容]。

2. /tdd - 测试驱动开发

用途: 遵循 TDD 方法论开发功能

流程:

  1. 定义接口
  2. 写失败的测试（RED）
  3. 实现最小代码（GREEN）
  4. 重构优化（REFACTOR）
  5. 验证 80%+ 覆盖率

为什么使用 TDD:

  • 确保代码可测试
  • 减少 bug
  • 更好的设计
  • 重构更安全

3. /code-review - 代码审查

用途: 全面审查代码质量

检查项:

  • 代码质量和可读性
  • 安全漏洞
  • 性能问题
  • 最佳实践遵循
  • 测试覆盖率

4. /build-fix - 构建错误修复

用途: 自动诊断和修复构建失败

适用场景:

  • 编译错误
  • 依赖问题
  • 配置错误
  • 类型错误

5. /verify - 验证循环

用途: 运行完整的验证循环

验证内容:

  • 所有测试通过
  • 代码覆盖率达标
  • 符合编码规范
  • 无安全问题

持续学习系统

两个版本:

v1 - 基础版

  • 从会话中手动提取模式
  • 使用 /learn 命令触发
  • 生成可复用的 skills

v2 - Instinct 版（推荐）

  • 基于信心评分
  • 可以导入/导出/演化

  • 学习后：Claude 自动知道项目偏好并应用

验证循环

两种验证模式:

1. Checkpoint 验证

特点: 在关键节点手动验证
使用场景: 大功能的里程碑检查

流程:

2. Continuous Evals（持续评估）

特点: 每次代码变更后自动验证
使用场景: 快速迭代开发

自动检查:

  • 测试通过
  • 代码覆盖率 ≥ 80%
  • 无 console.log
  • 无硬编码密钥
  • 符合编码规范

验证指标 (Pass@k):

  • Pass@1: 第一次尝试成功率
  • Pass@3: 三次尝试内成功率
  • Pass@5: 五次尝试内成功率

目标:

  • 简单任务：Pass@1 > 80%
  • 中等任务：Pass@3 > 90%
  • 复杂任务：Pass@5 > 95%

Rules（规则）

Rules = 始终遵循的指南

放在 ~/.claude/rules/ 的文件会被每次会话自动加载。

项目包含的 Rules

1. security.md - 安全规则

  • 禁止硬编码密钥、API token
  • 必须使用环境变量
  • 必须验证所有用户输入
  • 必须使用参数化查询（防 SQL 注入）

2. coding-style.md - 编码风格

  • 优先使用 immutable 数据结构
  • 单文件不超过 300 行
  • 函数不超过 50 行
  • 有意义的变量名

3. testing.md - 测试要求

  • TDD 优先
  • 代码覆盖率 ≥ 80%
  • 每个 PR 必须包含测试

4. git-workflow.md - Git 工作流

  • Commit 格式: feat/fix/docs/refactor
  • 每个 commit 只做一件事
  • PR 前必须 rebase

5. agents.md - 何时委派

  • 复杂功能 → 委派给 planner
  • 安全审查 → 委派给 security-reviewer
  • 大规模重构 → 委派给 refactor-cleaner

为什么接口优先？

好处:

  2. 并行开发 - 前后端可以同时开发
  3. 易于测试 - Mock 接口即可
  4. 防止过度设计 - 只实现需要的
