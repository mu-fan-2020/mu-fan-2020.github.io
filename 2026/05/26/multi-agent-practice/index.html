案例 1：用 Claude Code 多代理做全栈应用

需求

  • 用户能注册/登录
  • 创建、修改、删除待办
  • 待办支持标签和优先级
  • 部署到 Vercel

角色分配（Orchestrator-Worker 模式）

阶段化执行

阶段 1：规划（并行 ×3）

阶段 2：测试先行（TDD）

阶段 3：实现 — 主代理整合三方输出，开始写代码。

阶段 4：评审（并行 ×3） — code-reviewer + security-reviewer + database-reviewer

阶段 5：测试与修复 — e2e-runner 跑端到端测试，失败用 build-error-resolver 修。

效率对比

方式 耗时 缺陷率 上下文压力
单代理顺序 ~45 min 高 极高，频繁 compact
多代理并行 ~18 min 低 中等

避坑总结

  1. ❌ 不要让 Agent 写主流程代码 — 它们看不到完整上下文
  2. ✅ 让 Agent 输出建议或片段 — 主代理整合
  3. ❌ 不要在 Agent 里再调 Agent — 嵌套会让上下文丢失
  4. ✅ 每个 Agent 任务尽量原子化 — 一次只做一件事
  5. ❌ 不要省略测试 Agent — TDD 是质量的最后防线

案例 3：通过 MCP 接入外部工具

什么是 MCP？

MCP（Model Context Protocol）= AI 的”USB 接口”。Anthropic 在 2024 年提出的开放协议，让任何 AI 客户端能”插拔”外部工具/数据源。

MCP 与 Subagent 的区别

  • Subagent：独立 AI 实例，有自己的脑子
  • MCP：外部工具，被 AI 调用

它们是不同维度的东西！笨蛋别搞混！(￣へ￣)

MCP 生态推荐

  • mcp-server-github — GitHub 仓库操作
  • mcp-server-postgres — 数据库查询
  • mcp-server-slack — Slack 消息
  • mcp-server-notion — Notion 笔记
  • mcp-server-filesystem — 本地文件
